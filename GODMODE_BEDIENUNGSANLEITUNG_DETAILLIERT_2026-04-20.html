1) Schnellstart (Operator)

  1. Commander öffnen und Hub auto-check auf HTTP 200 bestätigen.
  2. Open synchronized Commander + Glasshouse + Operations ausführen.
  3. In allen 3 Fenstern Heartbeat prüfen: Commander/Glasshouse/Operations dürfen nicht Idle/Stale bleiben.
  4. Start bootstrap ausführen (falls nicht READY).
  5. Empfohlene Defaults anwenden (Full-29 + product_scope).
  6. Dispatch starten oder Prompt ausführen und Live Event Feed beobachten.
Wenn Glasshouse/Operations keinen Heartbeat haben, sind die Fenster meist nicht offen oder Browser-Popup wurde blockiert. In dem Fall Fenster explizit öffnen und erneut synchronisieren.

2) Detaillierte Betriebsanleitung

2.1 Preflight-Checks

CheckErwartungAktion bei Abweichung
Hub Health HTTP 200 Runtime neu starten, dann erneut Health prüfen.
Bootstrap READY Start bootstrap, danach /bootstrap/status prüfen.
Prompt Gate Prompt and autonomy controls are ready Control-Center Status neu laden, fehlende Service-Probes prüfen.
Routing Mode auto (Default) Nach Tests immer auf auto zurücksetzen.

2.2 Drei-Fenster-Betrieb

Commander

  • Steuerzentrale für Agent/Profil/Dispatch.
  • Empfohlen: 3D Web Game Full-29 Swarm mit product_scope.
  • Nur bei Bedarf auf Core-11 wechseln (schneller, weniger breit).

Glasshouse

  • Truth-Panel für Timeline, Lanes, Evidence, Interventions.
  • Pflichtblick auf reason, evidence ref, fallback/recovery.
  • Interventionen nur mit klarer Absicht: retry/reroute/rollback/quarantine.

Operations

  • Technische Diagnose (State Probe, Raw JSON, Config-Presence).
  • Verwendet für reproduzierbare Ursachenanalyse und Kontrollnachweise.

2.3 Dispatch- und Prompt-Flow

  1. Template laden (Transparent Swarm Run).
  2. Dispatch-Payload prüfen: Agent, Task, Repo, Branch, Profile.
  3. Dispatch starten oder Prompt ausführen.
  4. In Glasshouse prüfen: Schritte laufen durch, keine ungelösten Blocker.
  5. Bei Abbruch immer Evidence öffnen und reason zuerst auswerten.

2.4 Verifikation & Freigabe

Nur freigeben, wenn alle Pflicht-Gates grün sind:

  • Frontend: verify:release erfolgreich.
  • Backend: Unit-Tests erfolgreich.
  • Superbrain-Gate: PASS.
  • Deploy-Status: Vercel Ready.
  • Statusmodell: Endzustand Verified, kein offenes Implemented im Runtime-Output.
